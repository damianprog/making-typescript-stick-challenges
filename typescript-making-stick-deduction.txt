Skąd biorą się dwa wyniki naraz

Warunkowy typ z gołym parametrem (T extends ..., bez opakowania) jest dystrybutywny: kiedy T jest unią, TS nie wykonuje sprawdzenia raz na całej unii, tylko rozbija ją na człony, uruchamia typ osobno dla każdego i skleja wyniki z powrotem w unię.

IsTuple<[1] | number[]>
// TS rozbija:
//   IsTuple<[1]>       → true
//   IsTuple<number[]>  → false
// scala wyniki:
//   true | false
// normalizuje:
//   boolean

Każde pojedyncze wywołanie faktycznie zwróciło true albo false — dokładnie tak, jak napisałeś w definicji. Tylko że wywołań było dwa, bo argument był unią.

Jak to wyłączyć

Opakowanie obu stron w krotkę zabiera parametrowi „gołość" i wyłącza dystrybucję — wtedy sprawdzenie leci raz, na całej unii:

typescript
type IsTupleStrict<T> = [T] extends [readonly any[]]
  ? number extends T["length"]
    ? false
    : true
  : false;

type R2 = IsTupleStrict<[1] | number[]>;  // false

Dlaczego false? Bo [[1] | number[]] musi w całości być przypisywalne do [readonly any[]] — jest, więc wchodzimy w gałąź true. Tam T["length"] to 1 | number, co upraszcza się do number, więc number extends number → false. Sensowna odpowiedź: unia krotki i tablicy nie jest krotką.

skonczone na poczytac to jeszcze troszkę

[[1] | number[]] musi w całości być przypisywalne do [readonly any[]]

nie bardzo rozumiem jak unia [1] | number[] jest przypisywalna do readonly any[]

Reguła jest taka: unia jest przypisywalna do celu, gdy każdy jej człon jest przypisywalny.

[1]       extends readonly any[]  // true — krotka to tablica
number[]  extends readonly any[]  // true — tablica to tablica

Identyczne. Więc gdybyś sondował „jakiego typu jest element 0", te dwa typy byłyby dla ciebie nierozróżnialne — a pierwszy to krotka, drugi nie.

declare const b: (number | string)[];
